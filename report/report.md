## 一、实验目的

本实验在 Lab2 物理内存管理的基础上，学习 RISC-V 架构的中断与异常机制，建立从 Trap 发生、上下文保存、处理函数调用到上下文恢复和返回的完整执行流程，使内核不仅能够响应事件，还能够在处理后正确恢复原来的执行状态。

具体目标如下：

### 1.理解中断与异常的基本概念 区分时钟等异步中断与断点、非法指令等同步异常，理解它们的触发方式和返回行为。 掌握 Trap 相关寄存器及特权级机制。

### 2.理解 stvec、sepc、scause、stval 和 sstatus 的作用，明确 Trap 发生时硬件与软件各自承担的工作，以及 S 态 Trap 进入和返回过程中的状态变化。掌握上下文保存与恢复的方法。理解 struct trapframe 的内存布局及其与汇编保存位置的对应关系，在已有 SAVE_ALL 的基础上完成 RESTORE_ALL，保证被打断程序的寄存器和执行状态能够正确恢复。建立汇编入口与 C 处理函数之间的调用关系。按照 RISC-V 函数调用约定，将 Trap frame 的地址传递给 trap()，形成“汇编保存现场—C 语言处理—汇编恢复现场”的完整处理链路。实现基本中断与异常处理。实现持续的时钟中断、计数与统计输出，并在达到配置阈值后关机；实现断点和非法指令异常的识别、信息输出及返回位置调整。

### 3.理解中断控制与临界区保护。理解本地中断的开启、关闭及原状态恢复方法，认识其对物理内存管理等共享数据结构的保护作用，以及与原子操作、多核同步之间的区别。通过运行和调试验证实现。使用 QEMU、GDB 和官方测试检查 Trap 处理流程，结合独立测试验证寄存器恢复、指令长度判断、持续时钟和关机行为。

## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本实验围绕“正确进入 Trap、完成处理、恢复原执行流”这一主线展开。实现顺序为：先补齐基础依赖，再完成底层入口与返回，随后实现具体中断异常处理，最后通过测试验证完整流程。

### 2.2 功能的逐步实现

1. 补齐 Lab2 依赖，建立内核运行基础
   Lab3 的启动流程仍然需要执行物理内存初始化，因此首先补齐 page_init()，根据设备树提供的物理内存信息建立 struct Page 描述符数组，保留内核和管理信息占用的区域，并将剩余完整物理页登记给页分配器。同时补齐参与构建的 Best-Fit 分配器实现，保留 Lab3 已有的中断保护和自检逻辑，保证工程能够完整编译并完成初始化。

2. 设置 Trap 入口，准备接收事件
   内核通过 idt_init() 初始化 sscratch，并将汇编入口 __alltraps 的地址写入 stvec。本实验采用 Direct 模式，中断和异常均先进入同一入口，再由软件根据原因分发。

当某个 Trap 被送入 S 态处理时，硬件将返回位置、原因及附加信息记录到 sepc、scause、stval，更新 sstatus，然后跳转到 __alltraps。硬件不会自动保存全部通用寄存器，因此还需要入口汇编继续保存现场。

3. 保存上下文并调用 C 处理函数
   __alltraps 首先执行已有的 SAVE_ALL，在当前内核栈上分配空间，按照 struct trapframe 的布局保存通用寄存器及相关 CSR 值。

保存完成后，将当前 sp 指向的 Trap frame 地址放入 a0，按照 RISC-V 调用约定调用 trap(struct trapframe *tf)。这里传递的是保存区的地址，而不是复制一份上下文。

4. 根据原因完成中断与异常处理
   C 层由 trap() 调用 trap_dispatch()，根据 scause 的最高位区分中断和异常，再进入对应处理函数。

中断处理：对 S 态时钟中断，重新设置下一次时钟事件，每次将 ticks 增加 1，在达到 TICK_NUM 的整数倍时输出统计信息，并在累计输出达到配置阈值后调用 SBI 关机接口。其他已知中断输出类型提示，未知中断打印原因与现场。
异常处理：对断点和非法指令异常输出信息，并根据本实验支持的实际指令编码判断长度，调整 tf->epc，避免返回后重复执行同一条异常指令。其他异常使用 print_trapframe() 输出现场，作为诊断信息。
5. 恢复上下文并返回
C 处理函数返回后，执行 RESTORE_ALL，从 Trap frame 中恢复 sstatus、sepc 和通用寄存器。由于恢复过程仍需使用当前 sp 定位现场，因此原 sp 必须最后恢复。

随后执行 sret，由处理器根据 sepc 和 sstatus 中的返回状态继续原执行流，形成完整闭环

### 功能模块：Trap 上下文恢复与 Trap 入口功能（设计提示词借助 ai 完成）

**负责人：** 全员

#### 模块功能描述

**需要实现/修改的函数：**

```c
// 列出本模块涉及的所有函数签名
RESTORE_ALL：汇编宏，从 Trap frame 恢复处理器状态。
__alltraps：Trap 统一入口，保存上下文后调用 C 语言函数 trap()。
__trapret：Trap 返回入口，恢复上下文并执行 sret。
SAVE_ALL 已由现有代码提供，本模块沿用它创建的 Trap frame 布局，不修改其实现。
```

**功能说明：**

本模块负责连接 RISC-V 硬件 Trap 机制与 C 语言 Trap 处理流程。Trap 发生后，入口代码保存通用寄存器和特权状态，构造 Trap frame，并将其地址作为参数传给 trap(struct trapframe *tf)。C 处理函数返回后，汇编代码恢复保存的处理器状态，并通过 sret 返回 Trap 发生前的执行流。

主要场景：

Trap 入口时，复用 SAVE_ALL 保存的上下文，将 Trap frame 地址传给 trap()。

Trap 返回时，从 Trap frame 恢复特权状态、返回地址和通用寄存器，然后执行 sret。

恢复栈指针时，从 Trap frame 中取回 Trap 发生前的 sp，并确保恢复后不再依赖 Trap frame 的基址。

本模块与 kern/trap/trap.c 中的 trap() 和 struct trapframe 配合工作。Trap 类型的分类和具体处理由 C 语言 Trap 处理路径负责。

## 六、实验总结与收获

### 对操作系统的理解

1. 列出你们认为本实验中重要的知识点，以及与对应的 OS 原理中的知识点，并简要说明二者的含义、关系和差异

 **Trap 与上下文保存、恢复**：OS 原理中的 Trap 是处理器暂时转入内核处理事件的机制。本实验通过 `SAVE_ALL` 将寄存器和相关 CSR 保存到 Trap frame，通过 `RESTORE_ALL` 恢复，并用 `sret` 返回原执行流。两者的关系是：Trap 提供控制流转换，保存与恢复保证被打断的程序能够继续运行。本实验只实现了单核内核中的基本 Trap 路径，没有实现进程间上下文切换。

 **中断与异常**：中断通常由时钟等外部事件异步触发；异常与当前执行的指令同步相关。本实验通过 `scause` 的最高位区分两者，分别交给 `interrupt_handler()` 和 `exception_handler()`。时钟中断处理后返回原执行流；非法指令和断点异常则需要调整 `epc`，跳过触发异常的指令，才能避免反复触发。

**时钟中断与事件重设**：OS 原理中，定时器中断为时间统计、调度和抢占提供基础。本实验每次处理时钟中断都调用 `clock_set_next_event()`，重新设置下一次事件，并累加 `ticks`。如果不重设，就只能收到一次中断。本实验验证了持续中断，但尚未在中断中实现进程调度。

 **特权级与受控返回**：RISC-V 的 M、S、U 模式提供不同权限。当前实验内核运行在 S 模式，处理器进入 Trap 后记录返回位置和状态；处理完成后，`sret` 根据 `sepc` 和 `sstatus` 恢复执行。实验重点是 S 模式 Trap 处理，并未实现完整的用户态系统调用路径。

 **实验代码与原理的差异**：教材常从“保存现场—处理事件—恢复现场”描述 Trap；实际代码还必须严格匹配 Trap frame 字段偏移、RISC-V 调用约定和指令长度。例如 `x2/sp` 要单独保存并最后恢复，非法指令与断点异常返回时需按 16 位或 32 位指令长度更新 `epc`。

2. 列出你们认为 OS 原理中很重要、但在本实验中没有对应上的知识点
- 用户态进程通过系统调用进入内核，以及系统调用参数和返回值的传递；
- 多进程之间的上下文切换、抢占式调度和时间片分配；
- 多核情况下的中断路由、并发处理和同步；
- 完整的设备中断处理、驱动程序及中断控制器管理；
- 缺页异常的修复、按需分配和进程级错误处理。
